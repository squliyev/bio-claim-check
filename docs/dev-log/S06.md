# S06 — Europe PMC backend, cache and replay, shared contract suites

**Goal:** the first real backend. `retrieve QUERY` returns citable MEDLINE abstracts from Europe PMC, every
response can be cached and replayed byte-for-byte offline, and offline tests provably cannot reach the
network.

## Built

- **Cache (`engine/cache`, ADR 0009):**
  - A `BaseCache` port, with `InMemoryCache` and `SqliteCache` as implementations.
  - `CacheMode` is `off` / `read-write` / `read-only`.
  - `fetch_through` is the only place that decides whether to read, fetch or store. Read-only never
    fetches: a miss raises `CacheMissError` and no file is created.
  - Entries are first-write-wins and are never overwritten.
  - The cache key covers every input that shapes the request and nothing volatile.
- **Retrieval (`features/retrieval`, ADR 0008):**
  - `EuropePmcLiteratureSource` sends a MEDLINE-only, English-only query that also excludes non-research
    publication types (`query.py`).
  - `citable.py` decides whether a record is a citable abstract. Retracted papers are kept and marked.
  - `RetrievalError` covers transport, HTTP and payload errors. Retries happen only on transport errors,
    429 and 500/502/503/504, with backoff through an injected `sleep`.
  - `Paper` gained `doi`, `pmcid`, `license`, `open_access`, `publication_types`, `mesh_headings` and
    `retracted`.
- **CLI:**
  - Usage: `retrieve QUERY --k N --env-file`.
  - Exit codes: 2 = config, 3 = cache miss in read-only mode, 4 = retrieval, 5 = cache.
  - `build_retrieval` is a context manager that owns the HTTP client.
- **Shared contract suites** (`tests/contract/`) for both ports. A kind-based guard fails any port that
  has a backend but no suite, or a suite whose `IMPLEMENTATIONS` differ from the discovered ones.
- **Network block** (`tests/support/netblock`): IPv4/IPv6 `connect`, `create_connection` and DNS raise
  in every offline test, both in-process and in Python subprocesses (`sitecustomize` on `PYTHONPATH`).
  Only `live`-marked tests are exempt, and only they see `BCC_CONTACT_EMAIL`.
- **Live tests** (`make live`) check the real API against our assumptions: record shapes,
  publication-type spellings and the abstract cleaner.
- **Email-leak guard:** tracked and addable files may contain only `example.org`/`example.com` or
  GitHub no-reply addresses.
- **Docs:**
  - ADR 0008 (citable sources) and ADR 0009 (cache and replay).
  - A follow-up note on ADR 0001.
  - Invariants I31–I36.
  - Glossary entries (Citable paper, Retracted, `CacheMode`).
  - README usage and backlog B1.

## Decisions

- **Invariants renumbered.** The plan's I30–I34 became I31–I35 because I30 was already taken (S05b).
  Every code reference was remapped.
- **Golden reports changed, by design.** A structured diff shows that the only change is the 7 new
  `Paper` keys on each paper, with their default values (`publication_types` [], `retracted` false, the rest
  null). No claim, check or verdict moved. The characterisation run
  ids were re-pinned and a docstring note explains why.
- **`CacheMode.OFF` uses an in-memory cache**, so the policy path is the same in every mode and no file
  appears.
- **The live tests log; they do not print.** Only counts are logged, never the contact address.

## Verification

- `make verify` is green.
- **`make live`: 10/10 passed.**
  - 50 papers per seed query, 0 retracted.
  - Every excluded publication type matches real records: Retraction of Publication 21,178;
    Published Erratum 214,233; News 246,136; Editorial 820,507; Comment 1,073,174; Letter 1,457,376.
  - Cleaner: 120 abstracts and 1,282 sentences, with 0 leftover markup, 0 glued headings and 0 sentences
    that cannot be located in their abstract.
- **CLI demo:**
  - A read-write run fetched 5 papers.
  - A read-only replay printed byte-identical output.
  - An uncached query in read-only mode exited with code 3.
  - The contact address appeared nowhere in the output.

## Review triage

The plan review is triaged in §15.10 of the roadmap.

There was one implementation review, per process. Its fixes are verified by `make verify` and targeted
tests; they were not re-reviewed.

| # | Finding | Decision |
|---|---|---|
| 1 | `fetch_through` returned its own bytes after `put`, but a concurrent writer may have stored the key first, so two processes could disagree | **Adopt:** return the stored winner; `CacheError` if the cache did not keep the entry |
| 2 | `httpx.DecodingError` (a broken gzip body) escaped as a raw exception | **Adopt:** `RequestError` → `RetrievalError`, not retried |
| 3 | `SqliteCache` leaked `OSError` (the parent folder is a file); read-only mode on a directory gave an unclear error | **Adopt:** both become `CacheError` |
| 4 | A `hitCount` smaller than the records returned was accepted | **Adopt:** rejected as a contradictory payload |
| 5 | `NaN`/`Infinity` were accepted by `json.loads` | **Adopt:** `parse_constant` rejects them |
| 6 | An unreadable or non-UTF-8 env file crashed the CLI | **Adopt:** "Cannot read {file}: {error type}" (the content is never echoed), exit 2 |
| 7 | Connectionless UDP `sendto` is not blocked | **Reject:** no dependency uses it, and the block is a tripwire, not a sandbox. The I31 wording now says so |
| 8 | Configuration errors print several lines | **Reject:** listing every problem at once is more useful, and the output is shared with `config` |
