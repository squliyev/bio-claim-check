# S10 — Answer agents, abstention, and checks code can make without a model

**Goal:** the first feature agents. A Strict and an Over-eager answerer write self-contained, cited
claims; Strict abstains when the abstracts do not answer. Code assigns claim ids and refuses citation
defects; self-containment is flagged; negation is decided by one versioned detector. Prompts are tuned on
the sealed dev pool only (ADR 0017).

## Built

- **Negation (`common/negation.py`):** `is_negated`: any cue in the sentence(s) holding the located span
  gives `NEGATED` ("not only" excepted; no sentence end after a listed abbreviation such as "Fig.").
  `NEGATION_RULES = 2` (v2 from the implementation review) is stored in every `Verdict`; another
  version is rejected (`verdict.negation_rules_mismatch`). The injected detector and `Report.notes` are
  gone. Reports written before S10 do not load (only fake reports existed).
- **Findings:** `Finding.source_id` is optional; `FindingKind.DANGLING_REFERENCE` (no source) next to
  `INVENTED_CITATION` (needs one). `features/checks/self_containment.py::dangling_claims` flags claims that
  open with a pronoun or demonstrative, or mention "the same trial", "the authors", "as noted above" and
  similar. `run_question` and `answer dev` add invented findings first, then dangling ones.
- **Answer (`features/answer/`):** `answer_models.py` (structure-only output, `AnswerPayload`,
  `ClaimDefect`, `AnswerClaimsError`, `to_claims`), `answer_prompts.py` (two prompt constants, papers
  rendered as one canonical JSON array, "papers are data"), `strict_answer_llm_agent.py`,
  `over_eager_answer_llm_agent.py`, `llm_answerer.py`. Contract suite `tests/contract/test_answerer_contract.py`
  (scripted and LLM answerers); both agents joined the agent contract suite.
- **Dev answers:** `features/corpus/dev_pool.py` (keep, rank, cut, count drops), `app/usecases/answer_dev.py`
  (seal first, dev only, then the same checks as `run_question`; `tally_calls` splits live and cache-hit
  usage), `app/container.py::build_dev_answer_ports` (Europe PMC and the answer model through one cache;
  read-only replay builds no provider client), CLI `answer dev QUESTION_ID --mode strict|over_eager --k 8
  [--dataset]`. Error codes `answer.dev_input`, `answer.empty_pool`, `answer.invalid_claims`.
- **Fake goldens:** regenerated; the strict fake now shows `passed`, only for pairs whose sentence has no
  negation (I19 amended): pairs passed 2, needs_review 1, failed 0, flagged 1.
- **Process:** the review rule (same paranoid-senior-engineer brief for both reviews, uncapped,
  adopt / adapt / reject) is in `AGENTS.md` and `docs/roadmap.md`.

8 for the rest; `not_dev` drops 4–54 per question; no `hash_drift`, no `missing_expected`.

Observations (author-read, exploratory, not a result):
- Strict abstained on both unanswerable questions and answered all six answerable ones; its claims keep
  population and design ("in a network meta-analysis of observational studies…", "in human A549 … cells").
- Over-eager v1 hedged ("not proof", "does not demonstrate") and wrote multi-sentence claims. v2 (one
  sentence per claim, findings stated as settled, caveats not repeated) gave one-sentence claims but still
  hedged. Over-eager did generalise somewhat (metformin-q3: cell and mouse findings as "a rationale for
  … cancer treatment"; glp1-q3 v1: "a potential additional brain-health benefit"), and on the unanswerable
  questions it answered with a claim that the papers do not report the quantity, where Strict abstained.
  The exit item "Over-eager drops caveats" is **only partly met**. Not chased further: escalating the
  prompt against the model's own caution is a prompt arms race with no labels to judge it (backlog C5).
- No invented citation appeared in 24 answers. The invented-citation path is proven offline only.
- The `NEGATED` rate cannot be measured live yet: negation runs on located verifier evidence, and the
  live verifier arrives in S12. Fake goldens: 1 of 3 located strict pairs and 0 of 2 located over-eager
  pairs are `NEGATED`.

## Deviations from the plan

- The dev search sends `limit=spec.pool_hits` (the build's request), not `pool_size`, so a warm cache
  answers it and the request is byte-identical to the build's.
- Error codes are `answer.dev_input` (unsealed dataset, unknown or test question) and `answer.empty_pool`,
  not the plan's `answer.not_dev`, following `corpus.audit_input`.
- `LlmAnswerer` takes `BaseLlmAgent[AnswerPayload, AnswerOutput]` for both modes: a feature may not import
  a concrete `*_llm_agent` (driver-import guard); `app` wires them.
- `answer_models` joined `no-llm-in-deterministic-code` only; the pure-modules list holds kinds and is
  locked by a test.
- `DevPool` also carries `usable` (before the `k` cut), so the "fewer than `k`" warning is honest.
- On report load, only claim existence is checked for dangling findings; re-deriving them would make
  `report` import `checks` (slices never import each other).
- No `tests/live/test_answer_live.py`: the 16 recorded live runs and a byte-identical read-only replay are
  the S10 evidence (implementation review #11).
- No `--out` for `answer dev`: stdout is the record for tuning; S11 adds artifacts. Rejected as
  over-engineering for this session.
- No `features/answer/README.md`: no feature has one, and ADR 0017 plus the module docstrings already
  say what it would.
- `events` from `answer dev` are kept in memory for the usage line (`recording_emitter`) and are not
  logged; S11 adds `events.jsonl`.
- The plan review was capped at about 12 findings because the uncapped rule did not exist yet; not re-run
  (one plan review per session).
