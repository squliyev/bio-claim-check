# S13 — Trap generator (dev) and `traps verify`

**Goal:** give the frozen verifier a measurable catch rate. S13 plants known misreadings ("traps") with
predeclared ground truth, each paired with a clean parent claim, on dev only. The proof checkpoint then runs
`traps verify` on them (ADR 0022).

**Deviations from the plan, with reasons:**
- **No run recorder.** `RunInputs` is shaped around an answer run. `generate` and `verify` follow the
  challenge-run pattern instead: an attempt file under the var dir plus a tallying emitter that prints
  usage. Writer and verifier failures are still counted rows, and other errors abort (adapts triage #15).
- **The `verify` budget is twice the items**, not just the item count, because the verifier may repair once.
- **Container wiring moved from C to D**, beside the use case it serves.
- **Tests are flat** (`tests/unit/features/test_traps_*.py`, `tests/unit/app/test_traps_usecase.py`,
  `test_cli_traps.py`), matching the rest of the suite.
- **The neutrality guard (I75) is kind-based now.** It finds every `PromptTemplate` under `features`, so
  `TRAP_PROMPT` and any later prompt are covered without editing the test.
- **`TrapResult` and `TrapCounts` live in `counts.py`** to avoid an import cycle with `models.py`.
- **Each source goes to its scarcest kind in one pass**, so a larger `--per-kind` extends the order.
- **The rule floor goes through the same validity gate** as model drafts.
- **`traps verify` reuses `build_challenge_ports`**: the same verifier wiring the freeze cleared.
- **A `kinds` parameter was added as a test seam.** The fixture dataset has dev candidates for one kind
  only; the CLI always uses all five scored kinds.
- **`apply-audit` has no `--env-file`**, because it reads no settings.
- **`make schemas` does not apply.** Only interchange formats have schemas, and the challenge set has none
  either.
- **A test found a real bug in D:** `set_bytes` did not sort by id, so an unsorted set passed the canonical
  check. It sorts now.

**Found before the live run:** on the sealed dev set, `background_as_result` has 18 sieve candidates but only
9 within a dev question's pool, so the planned 12 per kind cannot be met for it. The maintainer chose to cap
it (draft all 9, report the shortfall) rather than lower every kind to 9 or widen the pool. Only a kind with
no source is refused now; `generate` prints each kind's count against the target.

## Limits

- **A controlled paired design, not naturalistic spin.** One call writes both claims, which favours lexical
  contrasts.
- **A silver standard, not ground truth.** The maintainer is not a biomedical researcher, so two LLM raters
  (gemini-4-argon, grok-4.7) confirm the rows and only unanimous rows are kept (ADR 0023). This probably
  keeps the easier traps and inflates the catch rate. Their isolation is instructed, not enforced, and the
  runs cannot be reproduced. The writer (`gpt-6.1-sol`) is the same deployment as the answerer.
- **Dev only, and exploratory.** Test traps need a later ADR and the test audit.
- **Small and unequal counts.** `background_as_result` has at most 9.
- **Self-reported results.** CI proves a result is consistent with its set, the dataset and its freeze, not
  that a model produced it.
- **Confirmed by the maintainer (2026-10-24):** ADR 0022 decision 8 and the `TRAP_PROMPT` wording,
  before the live run.

## Who confirms the set (ADR 0023)

The plan had the author confirm all 177 rows. The maintainer is not a biomedical researcher, so
`confirmed_by = author` would have been false. He chose (2026-10-25) a **hybrid**: a two-model panel now,
with an expert-confirmed dev-v2 later (C7), and **disagreements dropped**.

**A discarded advisory pass.** Before that decision, gemini-4-argon (high effort) read the sheet and
suggested 25 rejects. It had also read `VERIFY_PROMPT`, so its output is discarded and deleted from the var
dir before the panel runs. Its findings about the writer and the sieve went to the backlog (C8). A first draft
of the panel protocol carried three clarifications drawn from it; they were removed before any rater ran
(implementation review #10), so the protocol's definitions are the rule pack's, verbatim.

### Panel plan review triage (paranoid senior, 14 findings)

| # | Finding | Decision |
|---|---|---|
| 1 | A panel is not ground truth | **Adopt:** "silver standard" everywhere; ground truth reserved for the expert dev-v2 |
| 2 | Unanimity selects easy traps | **Adopt:** the bias direction is predeclared; the flow and 2x2 tables are reported; the metric is conditional |
| 3 | An adaptive top-up after the panel | **Adopt:** a fixed cohort of 177, no replacement |
| 4 | Family exclusion is not independence | **Adopt:** I79 is "declared family separation", and its limits are stated |

| 6 | A typed family is self-asserted | **Adopt:** a closed `RATER_FAMILIES`; the CLI takes the id only |
| 7 | Sheet hashes alone are unverifiable | **Adopt:** a committed ledger of votes (no reasons or claims); CI recomputes the set from it |

## Implementation review triage (paranoid senior, 9 findings)

| # | Finding | Decision |
|---|---|---|
| 1 | One-pass greedy assignment can leave a kind short that a matching would fill | **Reject, documented:** at the live target only `background_as_result` is short, and it has 9 eligible sources in total, so no assignment helps. A matching would reorder picks as `--per-kind` grows and break the cache-hit top-up. Recorded in `sampling.py` and ADR 0022 §6 |
| 2 | The sheet's abstract column was neither required nor checked | **Adopt:** required, and each cell must hash (formula-escaped or not) to the row's sealed `abstract_sha256` |
| 3 | CI did not check that a rule-floor claim is its parent's mutation | **Adopt:** `set_problems` recomputes `mutate(parent)` |
| 4 | Result provenance (seal, judge, verifier, family flag) was not attested | **Adopt:** `result_problems` checks the seal, the judge and verifier against the freeze record named in the file name, and recomputes the family flag |
| 5 | A pair's kind could be edited to one the source is not a candidate for | **Adopt:** the kind must be a scored sieve candidate of the source |
| 6 | Rank within `pool_hits` was not checked; papers were keyed by source only | **Adopt:** rank ≤ `pool_hits`; papers keyed by (question, source) |
| 7 | `TrapItem` allowed a rule-floor parent | **Adopt:** a parent must be a model draft and its own pair, as in `DraftRow` |
| 8 | An unknown writer aborted only after every verifier call | **Adopt:** the family flag is computed before any fetch; an unknown writer is an input error |
| 9 | `verify --name` could mislabel a result's freeze | **Adopt:** `--name` removed; the record is always named after `ACTIVE_FREEZE` |
