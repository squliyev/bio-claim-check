# S05b — Ports as base classes, transport-only infrastructure, rules that describe kinds

**Goal:** give every port one obvious shape before the first real backend lands (S06), move feature
knowledge out of `infrastructure`, and rewrite the architecture rules so a new slice, port or backend
passes them **without anyone editing them**. No behaviour change: the golden reports are byte-identical.

## Built

- **Ports (ADR 0007):** `ports.py` and `fakes.py` became `base_<thing>.py` (one `Base<Thing>(ABC)`) plus
  `in_memory_literature_source.py`, `scripted_answerer.py` and `scripted_verifier.py`. Every override
  carries `@override`; pyright `reportImplicitOverride = "error"` is on for src, tests and scripts. Test
  doubles subclass the bases.
- **Infrastructure split (transport only):**
  - `rulepack_yaml.py` → `strict_yaml.py` (generic `load_strict_yaml`: duplicate keys, anchors, merges
    and scalar types rejected, line numbers kept) and `text_files.py` (`read_text_file`, `read_package_text`).
  - `run_store.py` → `publish.py` (`publish_once(folder, name, data)`, single plain file names only;
    unique temp file, fsync, no-clobber `os.link`).
  - `parse_rulepack` (field-path errors) moved into `features/contracts/rulepack.py`; canonical report
    bytes and `run_id` moved into `features/report/canonical.py`.
- **Container:** `Container` became `RunPorts` (a frozen dataclass in `app/usecases/run.py`, so the use
  case receives its ports and imports nothing outward). `app/container.py` holds the composers
  (`load_rulepack`, `default_rulepack`, `publish_report`, `build_fake_run_ports`) that join a feature
  function with a transport function; the CLI calls only these.
- **Boundary packages:** `engine/events` (`[LEAF]`), `engine/pipeline` (processor bases arrive in S08)
  and `app/ui` (S17), each a docstring stating its rule.
- **Contracts** (`pyproject.toml`, now 10):
  - `core-has-no-driver-imports` → `pure-modules-import-no-drivers` (sources are the pure kinds:
    `common`, `engine.events`, `features.contracts`, `checks`, `report`, `bench.stats`,
    `annotate.agreement`).
  - New: `engine-is-feature-agnostic`, `infrastructure-holds-only-transport`,
    `driving-adapters-use-the-container` (with `allow_indirect_imports`, so `cli → container →
    infrastructure` is allowed) and `usecases-are-interface-free`.
  - `no-llm-in-deterministic-code` now covers every module whose docstring says "No LLM is involved"
    (14 sources); a parity test reads the docstrings.
- **Guards** (`tests/support/guards.py`, tests in `tests/arch/test_port_guards.py`): port shape, drivers
  only in backends, leaf packages, contracts import only common and leaves, no import-time registries,
  plus a subprocess test that importing every core package loads no driver. Every guard has an
  accepting and a rejecting test (parity-checked).
- **ruff `TID251`:** wall clock and randomness banned in all of `src` (`uuid5` stays allowed).
- **Harness:** `allow_indirect_imports` support; every rogue contract case has an allowed control.
- **Docs:** ADR 0007 (new), ADR 0002 rewritten for the new layout, invariants I12/I13 updated and
  I21–I30 added, AGENTS.md, backlog A7, `make graph` (infrastructure no longer imports features).

## Rule edits and why (ADR 0007 §9 requires this list)

| Rule | Edit | Why |
|---|---|---|
| `core-has-no-driver-imports` | Renamed and narrowed to pure kinds; the rest of the core is covered by the backend guard | Backends now sit beside their base and must import drivers; the rule now names kinds, not rings |
| `no-llm-in-deterministic-code` | 3 → 14 sources | The marker in docstrings is the source of truth; the list is forced by a parity test |
| Dependency policy | `app-only` → `driver` | Drivers are allowed in backends too, not only in `app` |
| Four new contracts | Added | One rule each; all name rings or packages, never instances |

## Decisions

- **The guard starts from classes, not file names** (plan review #3/#5): every concrete subclass of a
  `Base*` must live in `<prefix>_<base stem>.py`, so modules that are not ports are never touched.
- **Guards inspect at runtime** (import, `inspect.isabstract`, `__module__`) rather than AST name
  matching, which an imported or aliased class could spoof.
- **The no-registry guard covers `common`, `engine` and `features` only.** `app.cli` legitimately calls
  `add_typer` at import time.
- **Characterisation tests first:** CLI stdout, stderr and exit codes for every rule-pack error class,
  and the `run_id` = sha256(bytes)[:16] folder name, were pinned before the split and did not change.

## Verification

- Each new real-repo guard was proven to fire once by planting a violation and restoring the file:
  `sqlite3` in `scripted_verifier`, a `Protocol` in a base module, `engine.llm` in `engine.events` and in
  `contracts.ids`, a module-level call in `checks.citations`, `sqlite3` in `retrieval/__init__`.
- `git diff --exit-code -- tests/fixtures/golden/` is clean.

## Review triage

Plan review: §14.7 (10 findings) and §14.11 (10 findings) of the roadmap, all adopted or adapted.

Implementation review (one, per process). Fixes verified by `make verify` and targeted tests; not re-reviewed.

| # | Finding | Decision |
|---|---|---|
| 1 | The real-ports test asserted an exact port map, so adding a backend would need a test edit (contradicts ADR 0007 §9) | **Adopt:** kind-based: every `base_*.py` is a discovered port, discovery is non-empty, every port has a driver-free `in_memory_`/`scripted_` implementation; exact checks stay in synthetic cases |
| 2 | Registry guard missed `X = build_registry()` and calls inside top-level `if`/`try` | **Adapt:** guard walks top-level control-flow bodies and flags `regist*` calls; banning every module-level call that builds a constant is rejected (false positives on `re.compile`) |
| 3 | Clock/random gaps: `datetime.today`, `os.urandom`, `os.getrandom`, `monotonic_ns`, `perf_counter_ns` | **Adopt:** added to TID251 and the parametrized test |
| 4 | A backend importing another backend was not flagged | **Adopt:** backends are exempt only from the driver check; synthetic reject case added |
| 5 | `importlib.import_module("httpx")` / `__import__` bypass the driver rules | **Adapt:** `importlib.import_module` banned via TID251 (one line + test); `__import__` rejected: deliberate evasion, left to review |
| 6 | `read_package_text` raised raw `OSError`/`UnicodeDecodeError`; `default_rulepack` leaked them | **Adopt:** wrapped as `ReadError`, converted to `RulePackError`; tests for both; CLI output unchanged (characterisation tests green) |
