# S17a — Slim UI (demo track), plus checking one claim by PMID

**Goal:** the demo UI, in its final layered form (B4, roadmap "Demo track"):
- an Ask page;
- a "Check a claim" page (a claim plus a PMID);
- a Trust report page;
- an "About the verifier" section, with the complete S13p tables framed by ADJUST (ADR 0024 §3).

Maintainer decisions (2026-10-25):
- live runs from the UI;
- checking one claim by PMID is part of S17a;
- numbers appear only as the complete, labelled tables.

What is shown on the hackathon day is decided in H1 (option C).

## Plan review (paranoid senior engineer, 9 findings, all adopted)

| # | Sev | Finding | Decision |
|---|---|---|---|
| R1 | high | `ClaimCheck` lacked `Report`'s integrity validators | Adopt: an after-validator (ids, `verify_against`, live ⇔ verifier, FAKE ids) and tamper tests |
| R2 | high | A fictional check by PMID is impossible or counterfeit | Adopt: Fictional mode picks a `FAKE:` paper; a PMID is only for live or replay |
| R3 | high | The UI needs `contact_email`, so offline Docker without `.env` fails | Adopt: `UiSettings` without secrets; the full `Settings` is loaded only for a live action |
| R4 | high | Concurrent browser tabs can interleave ledger writes | Adopt: a process-wide lock around recorded commands; two processes at once stay unsupported (as `line_files` documents) |
| R5 | med | The run loader skipped the run-id/manifest hash chain | Adopt: one checked `load_published`, extracted from retractions |
| R6 | med | Ledger order gives duplicates and an ambiguous "newest" | Adopt: reverse the ledger, deduplicate by run id, label "most recently completed" |
| R7 | med | `copy.py` shadows the stdlib under `streamlit run` | Adopt: renamed `error_copy.py` |
| R8 | med | PMID validation too loose (the id is interpolated into a query) | Adopt: one strict `parse_pmid`; the backend also refuses anything but `MED:<digits>` |
| R9 | med | "Complete tables" was not guarded | Adopt: `AboutView` carries every row; an exact parity test against the JSON |

**Deviation:** the plan named a recorded Europe PMC id response as the fixture. The fetch tests use the
existing fictional `search_mixed.json` records instead, so no real paper enters the test fixtures.

**Deviation (D):** the plan said Live is *disabled* under `BCC_CACHE_MODE=read-only`. Instead it becomes
**Replay**, and stays enabled. In read-only mode `build_models` builds no provider client (the caching client
has no inner client), and retrieval reads a read-only cache, so any miss raises `cache.miss`. No click can
reach a provider, and the offline Docker demo can replay recorded runs and checks from the UI. Replay still
needs the full `Settings` (contact email), not API keys.

**Deviation (D):** I82 was planned as one `layers` contract. It is two contracts (a `forbidden` one that keeps
the three pure layers off the page, and an `independence` one between them), because the rogue-import fixture
harness (`tests/support/fixture_pkg.py`) cannot build the `|` layer syntax, and every contract needs a firing
case.

- in read-only mode no fetch callback and no provider client can be reached;

It ran after H1's commit B2, so no verdict on a would-be demo paper was seen before the picks were committed
(dev-log H1).

| Step | Run id | Result |
|---|---|---|
| Live `check` on a dev paper (`MED:23728174`, not a demo pick): "Exenatide halted motor decline in Parkinson's disease patients over 12 months compared with controls." | `2e8dc1d192c3be6d` | 1 verifier call. `flagged`, `overstated (certainty_inflation)`, quote located: the abstract says the single-blind rating "suggested" improvements |
| Live `run`: "Does exenatide slow motor progression in Parkinson's disease?" (strict, k=4) | `7070ca4b13a510c9` | 1 answerer call, 0 claims. The search returned four 2026 papers that do not answer the question, and strict mode made no claim. Recorded as it is; the retrieval is not tuned |
| `docker compose run offline` replay of both (`BCC_CACHE_MODE=read-only`) | same ids | `cache_hit=1` each, no live call, the same run ids |
| `docker compose up offline` | n/a | `/_stcore/health` answers `ok`; stopped with `docker compose --profile offline down` |

**Surprise, fixed:** the first replay failed closed with `Permission denied: datasets/SEALED`. Files written
by `publish_once` keep mode 0600 in the checkout, `COPY` keeps the mode, and the image runs as a non-root
user. The About page's `traps/results` file had the same latent bug, and CI did not see it because a fresh
checkout is 0644. Fixed with `RUN chmod -R a+rX,go-w traps datasets` and guarded by
`tests/arch/test_dockerfile.py`. The guard (I84) refused instead of running without its closed set, as
designed.

**Not done:** the replay was not clicked through in a browser. It ran through the same recorded path
(`record_check`, `record_question`) in the same image, and the 16 AppTest smoke tests cover the page's
Replay control.
