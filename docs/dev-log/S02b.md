# S02b — dependency-cruiser parity in Python

**Goal:** the checks a dependency-cruiser setup gives a TypeScript project (no circular imports, an I/O-free
core, every dependency accounted for, a generated graph), done with Python tooling.

## Tool choice (GitHub stars, 2026-10-20)

| Tool | ★ | Verdict |
|---|---|---|
| dependency-cruiser (JS) | 7.3k | The model we compared against |
| tach | 2.8k | Rejected: a second rule engine duplicating import-linter, with its own config; no per-rule isolation for our rule-fire harness |
| pydeps | 2.1k | Rejected: graph only; `import-linter drawgraph` already emits deterministic DOT |
| import-linter | 1.2k | **Kept and extended:** layers, independence, forbidden, `acyclic_siblings`, `drawgraph` |

## Built

- Contract `no-cycles` (`acyclic_siblings` over the whole package, depth 10).
- Contract `core-has-no-driver-imports`, with `include_external_packages = true`.
- A grimp guard: no module imports its own ancestor package. `acyclic_siblings` cannot see a package
  `__init__` that re-exports a child which imports the package back. A test documents that gap.
- Rule-fire harness: multi-edge cases, external targets, cycle evidence, an indirect driver chain.
- `tests/arch/test_dependency_policy.py`: every direct runtime dependency is classified; the policy
  matches the contract; the committed DOT graphs are fresh.
- `make graph` → `docs/architecture/{rings,features}.dot`. SVG rendering is deferred to the docs site (S22).
- Invariants I11–I14; ADR 0002, README, AGENTS.md and backlog updated.

## Rejected or deferred

- `no-orphans`: every module is a boundary today; revisit when code lands.
- Adapter independence inside `infrastructure`: deferred to S06, when adapters exist.
- `make explore` (needs the `[ui]` extra) and SVG in CI: cut as over-engineering.
