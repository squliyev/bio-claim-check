# S09 — Provider adapters, the LLM agent base and pipeline events

**Goal:** real LLM calls behind `BaseLlmClient` (Azure AI Foundry: gpt via the Responses API, Claude via
`AnthropicFoundry`), with honest usage, typed failures, deterministic retries, offline contract tests on
scrubbed recorded fixtures and a live `bio-claim-check llm ping`. Pulled forward by the maintainer: one base
for every LLM agent, and the pipeline event vocabulary, so every real call is observable from the first one.

## Built

- **Clock (`common/`):** `BaseClock`, `ScriptedClock`, `SystemClock`. `system_clock.py` is the one module
  allowed to read the wall clock (one ruff `TID251` per-file exemption, pinned by a test; ADR 0016 amends
  ADR 0007 §8). Shared contract suite `tests/contract/test_clock_contract.py`.
- **Events (`engine/events`, a `[LEAF]`):** `PipelineEvent`, `ModelRef`, stage events with `is_terminal`,
  `LlmCallStarted/Finished`, `LlmRepairRequested`, `LlmCallFailed`, `LlmRetryScheduled`; `EventEmitter`
  (stamps `at` from the clock); `BaseEventSink` with in-memory and logging sinks and a contract suite.
  `app/events.py` assembles the closed union and `parse_event`; `make schemas` writes
  `schemas/pipeline_event.schema.json`.
- **Runner:** `LlmRunner` emits per-attempt events, a repair event and one failure event before raising;
  client `BccError`s are re-raised unchanged. Validation locations the output schema does not declare are
  written as `<undeclared>` in events and error text.
- **Providers (`engine/llm`):** pure `openai_responses_codec.py` and `anthropic_messages_codec.py`;
  `transport_policy.py` (our retries); thin backends `openai_llm_client.py` and `anthropic_llm_client.py`;
  five new error codes (`llm.transport`, `llm.provider_rejected`, `llm.prompt_filtered`,
  `llm.unsupported_request`, `llm.unexpected_response`) plus `app.unsupported_provider` and
  `agent.declaration`; `LlmResponse.served_model`. Prompt-filtered calls count as **unmeasured**
  (`Spend.unmeasured_calls`), never as zero usage.
- **Agent (`engine/agent`):** `BaseLlmAgent[P, T]` (`[EXTENSION POINT]`), `AgentResult`, `PingLlmAgent`;
  the agent contract suite `tests/contract/test_llm_agent_contract.py`.
- **App:** `build_llm_clients` (SDKs built only here, `max_retries=0`); `llm ping [DEPLOYMENT…]` with
  `ExitCode.PROVIDER = 8`; pinned versions in `app/models.py`.
- **Fixtures:** `make record-llm` records `ok`, `truncated` and `repair_turn` for both providers through a
  scrubbing transport (`tests/support/llm_recording.py`) that refuses to write the host or key. Filter,
  refusal and throttling cases are synthetic. `tests/arch/test_llm_fixtures.py` checks labels, scrubbing and
  request-body drift.

## Live evidence (maintainer present)

- `llm ping gpt-6.1-sol claude-opus-4-8`: both ok. gpt-6.1-sol: input 68, output 13, reasoning 0.
  claude-opus-4-8: input 563, output 33. Forced tool use works on Opus 4.8 without thinking (risk closed).
- Recorded truncation: gpt ends `incomplete` / `max_output_tokens` (16 reasoning tokens at the 16-token API
  minimum); Claude ends `max_tokens`.
- Claude now reports `output_tokens_details.thinking_tokens`; the codec passes it through.
- Kimi was not adapted or pinged (deferred by the maintainer; backlog A10).

## Deviations from the plan

- **529 is retried:** Anthropic's "overloaded" status, added to the retry statuses. **504 is not** (implementation
  review): the gateway gave up, but the model may have run and billed.
- `httpx2` (the SDKs' HTTP library) became a direct driver dependency so backends can tell a refused
  connection (retried) from a dropped one (not retried).
- **Prompt filter:** a typed `llm.prompt_filtered` error and an unmeasured call replace D9's zero-usage
  response (plan-review finding 5).
- **Declarations are checked at construction**, not in `__init_subclass__` (I28; finding 1).
  `PingLlmAgent` lives in `engine/agent` (finding 2).
- **Agent contract suite** added (not in the plan), so every future agent proves the same properties.
- **`llm ping`'s table** is built from `PingResult`, not from the event sink; the logging sink shows events.
- **Truncated case** uses a fictional long reply ("the numbers 1 to 200 in words"), because the ping reply
  fits in the 16-token minimum and came back `completed`. The recorder now asserts `length`.
- **Cached-input** was not recorded (prompts are too short to hit the provider cache); synthetic tests only.
- **Claude pin = model id** (`claude-opus-4-8`): the Foundry portal shows no separate version.
- **Usage cross-check:** the OpenAI codec rejects a `total_tokens` that differs from input + output
  (found while comparing with a reference project's mapping layer). OpenAI's
  `input_tokens_details.cache_write_tokens` is inside input and ignored while prices are `None` (A13).
- **Location redaction:** the I59 sentinel test found a real leak: a key the model invents appeared in
  `LlmRepairRequested.problems` and error text. Fixed with `<undeclared>`.
- **Roadmap (D30):** S09 took the event vocabulary and emitters; S11 keeps the `events.jsonl` sink, run
  events, manifest, ledger and budgets.

## Implementation-review triage

One review (code-review agent) over `b60ed1f~1..HEAD` plus the docs. Six findings.

| # | Finding | Sev | Decision |
|---|---|---|---|
| 1 | The SDKs wrap every non-timeout network error as a connection error, so a connection dropped **after** sending (`RemoteProtocolError`, `ReadError`, `WriteError`) was retried up to 3 times, each possibly billed; 504 was retried for the same reason | high | **Adopt:** only `httpx2.ConnectError` (never sent) is retried; other connection errors and 504 give up with "may have been billed". `httpx2` is now a direct driver dependency. Tests over a mock transport for each error and for 504 |
| 2 | Spend is lost when the client raises something other than a prompt filter: earlier attempts' spend and a possibly billed timeout or unexpected 200 drop out of `Spend` | med | **Defer to S11** (backlog A14), where the ledger and budgets consume spend; today nothing aggregates a failed call's spend. Runner docstring and ADR 0016 now state the gap instead of claiming every failure carries spend |
| 3 | A 200 whose body is not JSON escaped as a raw `JSONDecodeError` (not a `BccError`, no failure event, ping crashes, and `.doc` holds the body) | med | **Adopt:** caught in both backends, raised as `llm.unexpected_response` with the cause dropped; test with a sentinel |
| 4 | `LlmCallFinished` reported the stored usage when a cache race was lost, not what this run paid; an S11 ledger from events would disagree with `Spend` | med | **Adopt:** the event reports `billed_usage` when set; test |
| 5 | ADR 0014 cites `pure-modules-import-no-drivers`, but the codecs and `transport_policy` are not in its sources, so nothing stops them importing an SDK | low | **Adapt:** probed by adding `import openai` to `transport_policy`: the I22 guard `test_only_backends_import_drivers` already fails (they are not backends). The contract cannot list them (its sources must also be "No LLM" modules, and codecs are LLM vocabulary), so ADR 0014 now cites the I22 guard. `httpx2` joined the contract's forbidden drivers |
| 6 | Docs named `PipelineEventUnion` and `request_key` (code: `AnyPipelineEvent`, `request_hash`); I60 claimed a `Finished` for every attempt | low | **Adopt:** names fixed in ADR 0016 and HANDOFF; I60 reworded |
