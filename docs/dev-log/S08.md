# S08 — LLM engine core (runner, cache key, honest cost)

**Goal:** one readable, replayable path for every LLM call, with measured token usage and an honest cost.
No provider SDK yet (S09); everything runs on `ScriptedLlmClient`, with and without the cache.

## Built

- **`common/models.py`:** `ValidatedModel`, `NonBlankStr` and `Sha256Hex` moved here from
  `features.contracts`, so the engine can use them (contracts re-import them; goldens and schemas are
  byte-identical). New `FrozenJson`: nested dicts and lists become read-only mappings and tuples, so a
  request cannot change after it is keyed. Non-string keys are rejected, never coerced.
- **`engine/llm`:**
  - `messages.py`: `Message`, `PromptRef`, `ModelIdentity`, `LlmRequest` (role-shape validator),
    `LlmResponse`, `FinishReason`.
  - `usage.py`: `Usage` (reasoning ⊆ output, cached ⊆ input), `Price` (finite, ≥ 0 `Decimal`, dated,
    sourced), `cost()`, `Spend`.
  - `model_spec.py`: `Provider`, `ModelSpec` (with the pinned `model_version`), `ModelCatalog` (fails
    fast on an unknown or duplicate deployment).
  - `errors.py`: `LlmCallError` with `LlmFailureKind`, attempts, `(loc, type)` problems and spend.
  - `base_llm_client.py`, `scripted_llm_client.py`, `caching_llm_client.py` (the inner client is optional
    only in read-only replay).
- **`engine/cache/policy.py`:** `fetch_through_result` returns the stored bytes and the live bytes
  separately, so a lost first-write race is billed correctly.
- **`engine/prompts`:** `PromptTemplate` (hash from text) and a strict `render` (missing or extra
  variables are an error; `$` in values is never re-substituted).
- **`engine/pipeline`:** `Invocation[P]` (payload vs request), the two `[EXTENSION POINT]` processor
  bases, and `LlmRunner` (schema from the output type, spend recorded before anything can fail, one
  repair for validation errors only, typed response processors).
- **`app`:** `app/models.py` holds our three deployments (prices and model versions not invented;
  prices are `None` until the user supplies them). `build_models` resolves every role and requires
  provider settings outside read-only.
- **Docs:** ADR 0012 (with the order diagram), the ADR 0009 follow-up, invariants I43–I47, glossary
  enums (`Provider`, `FinishReason`, `LlmFailureKind`), backlog A8.

## Decisions

- Tokens are provider-reported only. A local estimator lands with the pre-flight cost estimate (S16/S19).
- Unknown price means cost `None`, never 0. Cache hits add no cost.
- S08 ships no concrete processor and no `engine/budget` package: usage is runner-owned (plan review
  #1/#3). The first processors (S10/S12) bring their contract suite.

would be a blind except).

## Implementation-review triage

One review, 4 findings, all adopted. The fixes are covered by `make verify` and targeted tests, and were
not re-reviewed (policy: one implementation review per session).

| # | Finding | Decision |
|---|---|---|
| 1 | A request processor could switch the model after the identity check, or forge spend | **Adopt:** after each request processor the runner checks that model, responses and spend are unchanged, else `ProcessorContractError`; hostile-processor tests |
| 2 | A response processor could erase spend or responses, or rewrite the request | **Adopt:** response processors may change only the payload; checked after each one; tests |
| 3 | Pydantic validator messages could echo model-controlled values into the user-role repair turn | **Adopt:** the repair text and the error use `(loc, type)` only; a test with a validator that puts a secret in its message |
| 4 | `FrozenJson` coerced non-string keys, so `{1: …, "1": …}` collapsed into one key | **Adopt:** non-string keys raise; parametrised test, including nested |

## Bindings

- S09: each provider codec normalises usage to the engine contract (reasoning ⊆ output, cached ⊆ input)
  and tests it against that provider's raw usage shape; it supplies `model_version`.
- S12: maps `LlmFailureKind` → `FailureKind` in the feature, not in the engine.
- S16/S19: versioned local token estimator for the pre-flight cost estimate.
- The user: prices (with date and source) from the Foundry pricing page; until then cost is "unpriced".
