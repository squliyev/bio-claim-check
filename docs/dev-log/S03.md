# S03 — Text core (`common/text`)

**Goal:** the code every verdict depends on. `clean_abstract` makes the one text the model reads, the
checks match against and the UI highlights. `locate_quote` proves quoted evidence is in that text, by
position, and fails closed. `near_match` only routes a near miss to review (ADR 0005).

  profile name raises.

## Real markup inventory (Europe PMC, 300 abstracts, tag names and characters only)

The queries were metformin/cancer, GLP-1/Alzheimer's/Parkinson's and statin/neurodegeneration. A
throwaway script recorded tag names, entities and non-ASCII characters only. No abstract text was
stored or committed.

| Kind | Seen | Handling (each has a cleaner test) |
|---|---|---|
| Tags | `h4` (870), `i` (472), `b` (102), `sup` (92), `sub` (80), `bold` (8), `title`, `p` | `h4`/`title`/`p` block → space; `i`/`b`/`bold`/`sub` inline → removed; `sup` → `^` |
| `<sup>` content | digits, `-/-`, `+/+`, `+/-` (genotypes), `+`, `-9`, `th`, `®` | inner text kept after `^` (`Ink4a^-/-`) |
| Entities | `&#x2019;`, `&rsquo;`, `&beta;`, `&copy;`, `&#x03B2;` | unescaped after tag stripping |
| Spaces | thin U+2009 (333), NBSP (144), narrow NBSP U+202F (96), U+2005 (62) | NFKC → space |
| Dashes / operators | U+2011, en dash, `±`, `×`, `≥`, `≤`, `∼` U+223C, `≈` | hyphens → `-`; `∼` → `~`; operators are tokens |
| Letters / marks | β, α, κ, γ, ε, Δ, µ, μ, ², ₅₀, ⁺, °, ’, © | NFKC (µ → μ, ₅₀ → 50); superscripts → `^` |

Decision from the inventory: `~` and `≈` are operator tokens ("∼50%" is evidence), and `∼` is
normalised to `~`.

## Found while building

- **rapidfuzz alignment sides:** `dest_*` always indexes the second argument, even when rapidfuzz swaps
  internally because the quote is longer. An early draft swapped the sides. The probe caught it before
  any test was written.
- **Length-changing lowercase:** `'İ'.lower()` is two code points, which would shift near-match offsets.
  `_fold` lowercases only characters whose lowercase has length one. This has a test.
- **Idempotence:** removing a soft hyphen *after* NFKC leaves `e` + U+0301 uncomposed, so a second
  cleaning pass changes the text. Format characters are now handled before NFKC. An explicit cleaner
  row pins this, because the random property did not find it.
- **Mutation check of the properties:** five planted bugs. Four were killed by the properties: split
  decimals, a dropped sign, case-folding and no `+` operator. The fifth (the NFKC order) survived; the
  explicit row above now kills it.

## Review triage

### Plan review
16 findings: 15 adopted or adapted, 1 cut. The table is in the session plan; the summary is in
ADR 0005. The second pass changed the case rule to exact and made L18 negation binding downstream.

### Balance pass (mine)
- Cut: `:` as a token, the `CleanedText` construction guard, public `tokens()`/`normalise_quote`, and
  per-class property suites.
- Kept: `NEAR_MIN_TOKENS`, the coverage gate, the CI hypothesis profile and the tag inventory. Each
  costs about one line and removes a real risk.

### Implementation review
A paranoid review of the diff after `make verify` was green. Six findings, all fixed:

| # | Finding | Decision |
|---|---|---|
| 1 | `<jats:sup>5</jats:sup>` was stripped as an inline tag, so `10^5` became `105`: a false *located* | **Adopt:** `<sup>` accepts a namespace prefix; tests for digits, negative exponent, genotype |
| 2 | A quote matched a token run glued to its neighbours: `5 mg` in `5 mg/kg`, `5 cells` in `10^5 cells`, `ER+` in `ER+/-` | **Adapt:** the whole-expression rule (no text token may touch either end of the span) instead of the suggested per-class special cases. L30 rows; the property oracle models touching; a mutant without the rule is killed |
| 3 | Any `<word …>` was stripped, so prose such as `a <b and c> d` or `p<q and r>0` lost text | **Adopt:** an allow-list of known tag names and an attribute grammar that requires values; unknown tag-like text stays literal |
| 4 | Symbols outside the operator list were ignored, so `10 C` matched `10 °C` and `R D` matched `R&D` | **Adopt:** every non-space symbol is a token except prose punctuation, brackets and quotes. L31 rows; `°`/`&` items added to the property alphabet |
| 5 | ADR 0005 and I15 did not describe the new rules | **Adopt:** both updated |
| 6 | "Every L-row is a test" was inaccurate (L15 has its own test; some rules have several rows) | **Adopt:** wording is now "rules L1–L31" |

Balance: rejected the suggested per-symbol special cases for #2, because one rule covers every case and
is checked by the oracle. Not fixed: the tag regexes are quadratic on pathological input (20 000
unclosed `<sup>` in 100 k characters takes ~7 s). Real abstracts are a few thousand characters, so this
is recorded in ADR 0005 rather than engineered around.

### Deviations from the plan
- The invariant is **I15**, not I16 (there was no I15).
- `~` and `≈` are tokens and `∼` → `~` (from the inventory).
- Format characters are handled **before** NFKC (idempotence).
- After the review, every non-space symbol is a token, not a fixed operator list.
- The token match must be a whole expression (finding #2).
