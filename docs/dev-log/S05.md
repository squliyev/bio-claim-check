# S05 — Walking skeleton (fakes end to end)

> **Superseded in part by S05b:** `ports.py`/`fakes.py`, `Container`, `run_store` and `rulepack_yaml` were replaced (ADR 0007). This note is kept as history.

**Goal:** `bio-claim-check run "<question>" --fake` goes retrieve → answer → checks → verify → report
through real ports, real contracts and the real composition root, with deterministic fakes behind every
port. Fake output must never be mistaken for a result.

## Built

- `features/contracts/`:
  - `paper.py`: `Paper(source_id, title, year, raw_abstract)`. `.abstract` is a plain property that runs
    `clean_abstract` on every access; it is never stored, so it cannot be forged or go stale.
  - `answer.py`: `Answer(question, mode, claims)`, unique claim ids; zero claims is a valid abstention.
  - `finding.py`: `FindingKind.INVENTED_CITATION`, `Finding`.
  - `labels.py`: `AnswerMode` (`strict`, `over_eager`).
  - `verdict.py`: `CitationNotRetrieved` (always `flagged`); `PairOutcome = Verdict | VerifierFailure |
    CitationNotRetrieved`; `claim_disposition` accepts all three. `_Validated` became the public
    `ValidatedModel` so the new contracts share its copy guard (the S04 log keeps the old name).
- Ports, one file each: `retrieval/ports.py` (`LiteratureSource`), `answer/ports.py` (`Answerer`),
  `verify/ports.py` (`Verifier`, one call per (claim, source) pair).
- Fakes: four fictional papers `FAKE:1`–`FAKE:4` with real-looking markup (`<h4>`, `<i>`, `<sup>`,
  entities); a strict script (3 claims) and an over-eager script (6 claims, one citing `FAKE:99`); a
  scripted verifier that builds verdicts only through `Verdict.finalise`.
- `features/checks/citations.py`: `invented_citations` (deterministic, ordered, one finding per pair).
- `features/report/`: `Report`, `ClaimReport` and a tagged pair union (`verdict`, `failure`,
  `citation_not_retrieved`); `build_report`.
- `app/container.py` (`Container`, `build_fake_container`), `app/usecases/run.py` (`run_question`).
- `infrastructure/run_store.py`: canonical JSON bytes, `run_id` = first 16 hex of their sha256, atomic
  write (unique temp file in the run folder, fsync, no-clobber `os.link`); identical bytes are a no-op, different bytes
  refuse.
- CLI `run QUESTION [--fake] [--mode strict|over_eager] [--k N] [--out DIR]`. Without `--fake` it exits 2
  ("live runs arrive in S12"). The fake path never loads `Settings`, so it needs no `.env`.
- Tests: contracts, fakes/checks, report integrity, use case (spy, forging verifier, edge cases), run
  store, and e2e golden files for both modes with hand-computed counts, plus a subprocess test of the
  installed console script with a hostile `.env` and `BCC_*` variables.
- `--update-golden` pytest option: rewrites, then fails on purpose; refused when `CI` is set.
- Docs: ADR 0006 (decision 3 gains `CitationNotRetrieved`), ADR 0002 (container and use cases built),
  glossary (`AnswerMode`, `FindingKind`, terms), invariants I18–I20, README quick start, backlog A6 ✅.

## Decisions

- **Fakes sit behind the domain ports, not behind an LLM client.** `engine.llm` arrives in S08; each later
  adapter replaces one port.
- **Derived values are accepted on load only if they equal the recomputed value.** The plan said derived
  fields are "never accepted as input", but then a genuine `report.json` could not be reloaded. A wrap
  validator pops the derived keys, validates the inputs, recomputes and rejects any mismatch, so a forged
  or stale count still fails (I20).
- **Integrity is checked twice:** the use case runs `verify_against` on every verdict from the port, and
  the `Report` validator re-runs it, so a loaded file is checked too.
- **`run_id` is not inside the report**; it names the folder, so the hash is not circular.
- **No snapshot dependency:** two committed golden files and a pytest option.

## Review triage

Plan review: 18 findings, triaged in the roadmap (§13.8); 17 adopted or adapted, symlink rejection
rejected (a local single-user tool writing to a folder the user chose).

Implementation review (one, per process): 3 findings.

| # | Finding | Decision |
|---|---|---|
| 1 | `Report.model_validate(existing_instance)` skips revalidation, so a nested verdict tampered with via `object.__setattr__` survives | **Reject:** it needs a deliberate bypass of frozen models, which Python cannot prevent (same reasoning as S04 #2). The trust boundary is loading JSON, which is fully validated, including derived values |
| 2 | Check-then-`replace` race: a concurrent writer could be overwritten; the PID temp name collides across threads | **Adopt:** a unique `mkstemp` temp file, then a no-clobber publish with `os.link`; `FileExistsError` falls back to compare-or-refuse. A forced-race test (the racer publishes during fsync) was mutation-checked against `replace` |
| 3 | A predictable temp name lets a pre-planted symlink be followed | **Adopt via #2:** `mkstemp` is random and `O_EXCL`. Rejecting a symlinked output folder stays rejected (plan triage #5) |
