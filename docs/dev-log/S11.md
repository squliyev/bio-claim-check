# S11 — The run record

**Goal:** every command attempt leaves a durable, honest record: a canonical result, a trace, a ledger
row; a cap on live calls; and the S09 spend gap (backlog A14) closed through events (ADR 0018).

## Built

- **Run record (`app/run_record.py`):** `RunManifest` (no time, path, host or cache mode), `LedgerRow`,
  `llm_uses` (distinct agent/model/prompt/served-model tuples from events), and the `recording` state
  machine with `RunRecorder.prepare`. The run id is the first 16 hex of sha256(manifest). The artifact is
  published, then the manifest last, only after the body ended and the trace closed cleanly. Every
  attempt appends one ledger row: `succeeded`, `failed` (its `BccError` code, or `run.internal`) or
  `cancelled` (`run.cancelled`). `app/container.py::record_io`/`record_run` inject the file operations.
- **Trace:** `engine/events/jsonl_event_sink.py` (one canonical line per event, flushed),
  `tee_event_sink.py` (memory first, then file), `errors.py` (`events.write`). Trace names are
  `<UTC start>-<n>.jsonl` with exclusive create, `n` ≤ 99 (`infrastructure/line_files.py`).
- **Ledger file:** `infrastructure/line_files.py::append_line`: `O_APPEND`, a write loop, fsync; any
  failure truncates back and raises one `files.append`.
- **Usage:** `engine/events/call_tally.py` (moved from `answer_dev`), per model, fields named by unit;
  `LlmCallFailed.unmeasured` is set at the `client.complete` call; a post-live cache failure is
  `CacheWriteError` and unmeasured; a trace-write error passes through the runner, and the original error
  wins over a failed failure-event write. I44 narrowed; A14 ✅.
- **Budget:** `engine/llm/budgeted_llm_client.py` (`CallBudget`, `BudgetedLlmClient`,
  `llm.budget_exceeded`) wraps the live client inside the cache; `BCC_MAX_LIVE_LLM_CALLS=40`.
- **Commands:** `run --fake --var-dir` (replaces `--out`) and `answer dev` record; `answer dev` publishes
  `answer.json` (`DevAnswerRecord`: ids, counts, claims, findings, no abstracts). Stage events for
  `run`, `retrieve`, `answer`, `verify`. Schemas for the manifest and ledger row.
- **Docs:** ADR 0018; I65–I68; glossary; error codes; README; roadmap; HANDOFF.

## Deviations from the plan

- `infrastructure/line_files.py` (append and numbered files together) instead of `append.py`.
- `summed()` kept in `call_tally` for the CLI line (R2-17 cut only `total()`).
- Start/finish pairing is lenient: it never raises; a repeated start closes the earlier one as never
  ended (unmeasured). R2-12's typed interleave error was dropped: the runner is sequential, and an error
  in the fold would lose the row it exists to write.
- `EventWriteError` lives in `engine/events/errors.py` and `LlmBudgetExceededError` in
  `engine/llm/errors.py`: the port-shape guard allows one public class per `base_*.py`, and the runner may
  not import a `*_llm_client.py` backend module.
- New codes `run.input` (blank question, bad `k` in `run`) and `answer.dataset` (dataset problems,
  apart from question problems), so preflight failures are typed inside the recorder (R2-7).
- A cache read-back failure right after a live fetch is also `CacheWriteError` (the call was made).
- Schemas for the manifest and ledger row were added (`make schemas`).

## Bindings

- S12's live `run` records through `record_run`, wraps every live client in the one `CallBudget`, and
  its manifest names the verifier's model and prompt hash.
- The run id includes the package version: a release changes every run id (accepted, plan #23).
- No ledger reader exists yet; locking and tail repair wait for one.
