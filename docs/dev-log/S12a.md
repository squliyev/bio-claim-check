# S12a — The LLM verifier and the first live `run`

**Goal:** the real verifier (one isolated call per claim–source pair), the first live `run`, a dev path
for tuning, a recorded model-family check and a separate retraction re-check (ADR 0019). The roadmap's
S12 was split by the maintainer: tuning, the dev smoke gold set and the prompt freeze move to S12b.

## Built

- **Verify slice:** `VerifyPayload` (claim, title, cleaned abstract, rule pack), `VERIFY_PROMPT` (four
  labels in precedence order, verbatim quote, papers and rules as JSON data), `VerifyLlmAgent`
  (`verifier`) and `LlmVerifier`, which maps only output-level failures to a counted `VerifierFailure`
  and lets everything else stop the run (I69, I70).
- **Models and report:** `ModelFamily`/`ModelSpec.family` per deployment; `Report.provenance`
  (`fake`/`live`) with a derived notice (`LIVE_NOTICE`); `Report.models` with a computed `same_family`,
  `null` for fake runs (I71). Fake goldens changed only by `"models": null`.
- **Run record:** `RunDetails.declared_llm` names each role's prompt hash from the wiring, so the run id
  names the verifier prompt even when no verifier call finished.
- **Flow:** `check_answer` (answer, checks, verify, build) shared by `run_question`, the live `run` and
  `run_dev` (`DevRunRecord`: report, kept ids, usable, dropped by reason); `dev_papers` factored out of
  `answer_dev`. `build_live_run_ports` wires both agents under one `CallBudget`.
- **CLI:** `run QUESTION` (live), `run --dev QUESTION_ID`, flag checks (INPUT), the same-family warning;
  `retractions RUN_ID`.
- **Retractions:** `BaseLiteratureSource.retraction_status` (in-memory and Europe PMC: by id, no citable
  filters, chunks of 100, uncached; unexpected or duplicate records refused); `app/usecases/retractions.py`
  checks the run's hash chain before any request and folds the rows; the record goes to
  `var/retractions/<run_id>-<UTC>-<n>.json`. New code `retractions.input`.
- **Docs:** ADR 0019; I69–I71; glossary; error codes; roadmap (S12 split); backlog B3 ✅; HANDOFF.

## Deviations from the plan

- `retraction_status` was added to the existing `BaseLiteratureSource` and its two implementations,
  instead of a new `BaseRetractionSource` port plus a `europe_pmc_wire.py` split: the backend, its
  parser and its contract suite are shared, and a second port would duplicate them (less code, same
  checks).
- No JSON schemas for the retraction-check record or `VerifyPayload`: there is no outside consumer yet.
- The retraction record is one compact canonical JSON line, like the other records.
- The claim is rendered as JSON too, not only the paper and the rules, so it cannot escape its string.
- `LlmVerifier` has no `except LlmPromptFilteredError` branch: the runner already raises a filtered
  prompt as `LlmCallError(CONTENT_FILTERED)`, so the branch was unreachable.
- `verify_prompts` is not in the no-LLM contract (like `answer_prompts`): `PromptTemplate` imports
  `engine.llm.messages`.
- A shared test-support module `tests/support/live_run.py` scripts the provider for the CLI tests.
- No separate `test_run_dev.py`: `run_dev` is covered through the CLI dev-run test and `answer_dev`'s
  preflight tests (`dev_papers`).
