# S07a — Evaluation corpus code: spec, sieve, clusters, split, `corpus build`

**Goal:** all the code that turns a pre-registered question spec into a frozen dev/test corpus. It is
tested end to end on fictional papers, so S07b only has to commit the spec, fetch live data and seal it.
No real abstract was fetched or read in this session.

## Built

- **Contracts (`features/contracts/corpus.py`):** `CorpusSpec`, `Domain`, `Question`, `SourceEntry`,
  `Evidence`, `QuestionEntry` (query, pool size and pool hash), `CorpusManifest` (with the NLM notice) and
  `CorpusSplit`. The spec is parsed from strict YAML; every error names its field path.
- **Corpus slice (`features/corpus`, no LLM):**
  - `eligibility.py`: the never-candidate exclusions (retracted, reviews, unknown publication types,
    MeSH not indexed) and sieve v1 for the four trap kinds (ADR 0010 table).
  - `clusters.py`: union-find over NCT ids (title + cleaned abstract) and normalised titles; the salted
    hash split; held-out clusters always go to test.
  - `serialise.py`: canonical JSONL and the abstract hash.
- **Use case (`app/usecases/build_corpus.py`):** searches each question once (cutoff and pool of 100),
  merges the pools by source id, applies the sieve, clusters, splits and serialises. It raises
  `PoolConflictError` if one source comes back with different metadata from two queries.
- **CLI:** `corpus build --spec --out --declared-fetched-on [--env-file]`; exit 6 when an output exists
  with different bytes or cannot be written. Publishing writes the data files first and the manifest
  last.
- **Throttle:** `EuropePmcLiteratureSource` waits 1 s before every real request after the first; cache
  hits never wait.
- **Docs:** ADR 0010 (corpus and split) with an index row; the ADR 0008 NLM-terms amendment; invariants
  I37–I39; glossary terms; the README `corpus build` section; backlog B2 🚧 and B2b ⏸.
- **AGENTS.md:** every session plan carries code sketches and a file tree with a reason per file.

## Decisions

- **`build_corpus` joined the `no-llm-in-deterministic-code` sources.** It carries the "No LLM" marker,
  and the marker-parity test requires every marked module to be covered. Rogue cases are generated.
- **Publishing order:** all destinations are checked first (manifest included), then the data files are
  written in sorted order, then the manifest. A manifest therefore only ever sits over complete, matching
  data.
- **`surrogate_as_clinical`** stays out of v1 (B2b): it needs a sieve v2 and its own ADR.
- **The spec is hashed as written.** Question order is part of the pre-registered spec, so the manifest
  hash changes with it; the data files do not (I37 wording narrowed to say exactly that).
