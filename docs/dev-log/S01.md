# S01 — Tooling skeleton

## Built
- Project `bio-claim-check` (import `bio_claim_check`, CLI `bio-claim-check`), uv + hatchling, `src/` layout,
  Python 3.13, `uv.lock`.
- Ring packages (`common`, `engine`, `features`, `infrastructure`, `app`) with docstrings stating each ring's rule.
- `app/settings.py`: pydantic-settings, `BCC_` prefix, `extra="forbid"`, `SecretStr` secrets, cross-field rule
  "live cache modes need at least one provider".
- CLI: `--version`, `config` (validates and prints settings with secrets redacted; errors never echo input).
- Tooling: ruff (incl. BLE, T20, S, TID251 banning `os.environ`/`os.getenv`), pyright strict, pytest with
  strict markers and warnings-as-errors, Makefile (`make verify`), pre-commit (pinned by SHA) with gitleaks.
- `.gitleaks.toml`: extra rule blocking real Azure AI endpoints; only placeholders are allowed.
- CI: one step per gate, all actions pinned by SHA, gitleaks image pinned by digest, JUnit artifact + report.
- Dependabot for actions, uv and Docker. Dockerfile: digest-pinned bases, `--frozen`, non-root.
  Compose mounts only `./var`; `.env` is passed as environment, never mounted.

## Decisions
- **Name:** `claimcheck` is already taken on PyPI by a project in the same space ("zero-LLM claim
  verification"). Renamed to `bio-claim-check` to avoid confusion.
- **Env prefix `BCC_`** so variables never collide with provider SDK variables (`OPENAI_API_KEY` etc.).
- **Git identity:** the repo-local `user.email` is a GitHub noreply address; the global config is not used.
- Dependencies are added in the session that first needs them (httpx in S06, structlog in S11), not upfront.
